# Brulion — notes for contributors and coding agents

Offline-first Markdown notes app (Obsidian-style files + Logseq-style block outliner and
journals, calendar, reminders/alarms, calculations, Syncthing/Nextcloud sync) written in
**C++20 + Qt 6.11 (Qt Quick/QML)** for NixOS/Linux, Android and the browser (WebAssembly).
Read before changing code:

* `docs/SYNTAX.md` — the Markdown dialect (single source of truth for parsing/rendering).
* `docs/ARCHITECTURE.md` — layers, modules, platform strategy.
* `docs/UI.md` — QML UI, block editor, navigation, components.
* `src/core/types.h` — shared data model. Change only when strictly needed, keep compatible.
* Branch `archive/web-v1` holds the previous TypeScript/Tauri implementation (well-tested
  logic for dates, markdown, calc, sync, storage, platform + an Android Kotlin plugin). Use it
  as a reference and port test cases from it: `git show archive/web-v1:src/core/dates/natural.ts`,
  `git ls-tree -r --name-only archive/web-v1 src/core`.

## Commands (inside `nix develop`)

* `scripts/dev-build.sh` — configure + build `./build` (Ninja, ccache, Debug, -Werror).
  `scripts/dev-build.sh -t tst_dates` builds and runs tests matching a regex.
  `BUILD_DIR=build-foo scripts/dev-build.sh` uses another build dir.
  The script holds a machine-wide lock: only one compilation at a time on this machine.
* Run the app from the build dir: `./build/src/app/brulion` (`QT_QPA_PLATFORM=offscreen` for
  headless smoke runs; screenshots via the app's `--screenshot` option once it exists).
* `nix build .#brulion` — the Nix package (runs the tests).

## Resource limits on the dev machine (important)

The dev machine is a Raspberry Pi 4 (aarch64, 3.7 GB RAM) that crashed once from memory
exhaustion. Always build through `scripts/dev-build.sh` (default `-j2`, locked); never start
parallel compiles or several GUI processes. Heavy builds (Android, WebAssembly, full release
builds) run on the x86_64 laptop via `flock <lock> laptop-run …` or in GitHub Actions.

## Conventions

* C++20, Qt types (`QString`, `QList`, `QHash`, `QDate`…), `namespace brulion` (sub-namespaces
  allowed). `#pragma once`. `QT_NO_KEYWORDS` is set: use `Q_SIGNALS`, `Q_SLOTS`, `Q_EMIT`.
  `QT_NO_CAST_FROM_ASCII`: use `QStringLiteral`/`u"..."_s`/`QLatin1String`.
* `src/core` is GUI-free (QtCore + QtNetwork; `src/core/io` may use QtGui for
  `QTextDocument`). No platform `#ifdef`s in core — platform code lives in `src/platform`.
* One directory per core module (`src/core/<module>/`) with its own `CMakeLists.txt` that
  calls `target_sources(brulion_core PRIVATE …)`; it is picked up automatically. Tests:
  `tests/core/<module>/CMakeLists.txt` with `brulion_add_test(tst_<name> SOURCES …)`. Never
  edit another module's CMake files.
* Tests: QtTest (`QTEST_GUILESS_MAIN` for core), data-driven (`_data()` functions) where
  sensible, Polish text with diacritics (ąćęłńóśźż), edge cases, malformed input.
* Dates: reminders are local wall-clock time (`DateSpec`); never convert through UTC.
* Content edits are pure functions (content in → content out) or `BlockDocument` operations;
  line endings and untouched text are preserved byte-for-byte.
* Security: notes come from anywhere (imports, sync). Rendered rich text is generated by our
  `InlineRenderer` with escaping — never pass raw note HTML to QML `Text`. The calculator is
  our own parser (no script engine evaluation of note content).
* UI strings: `qsTr()`/`tr()` with English source text; Polish translation in `i18n/`.
* Comments and identifiers in English; user docs in Polish (README has an English section).
